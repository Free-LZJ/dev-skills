# 文档集

需要创建、迁移或精简 requirements-delivery 工作文档时读取本文件。

## 选择原则

不默认创建文档集。每个文件必须解决一个当前存在的问题；没有独立职责就不创建。

| 文件 | 创建条件 | 权威内容 |
|------|----------|----------|
| `开发清单.md` | 多 Task、跨会话或需要交付状态 | Task 总览、依赖关系、推荐顺序、逐 Task 明细、详细设计索引、阶段化状态、验收信号、验证矩阵、证据和下一步 |
| `系统分析.md` | 需求与代码/模型存在重要差异或关键边界需长期保留 | 事实、差异、结论、范围、风险 |
| `详细设计.md` / `<阶段>-详细设计.md` | 跨模块契约、复杂数据流、权限、迁移、并发或回滚 | 可直接落地的实现级设计、关键代码或完整伪代码、长流程 Mermaid |
| `当前上下文.md` | 长周期、多参与者且开发清单不足以恢复 | 活跃 Task、有效结论、阻断、下一步 |
| `测试计划.md` | 多环境、多阶段或多类型验证需要矩阵 | 测试范围、状态和证据索引 |
| `过程记录.md` | 审计、复盘或必须保留的长篇历史 | 历史过程 |

小任务不创建这些文件。普通跟踪任务从 `开发清单.md` 开始，其他文件按风险增加。

## 单一来源

- 当前 Task 状态只写在 `开发清单.md`。
- 分析结论只写在 `系统分析.md`；详细设计引用它，不复制整段背景。
- 实现设计只写在 `详细设计.md`；开发清单中的每个父、子 Task 都必须保留设计定位字段。已创建详细设计时必须链接对应的具体章节；未创建时写 `不涉及（未创建详细设计）`，不为满足格式强造设计。
- 验证证据优先写在开发清单；存在测试计划时改为引用测试计划。
- 历史只写在过程记录，活跃文档只保留当前结论。

结论变化时更新权威来源和直接受影响的 Task。不要为保持表面一致而修改无关文档。

## 文件内容

### 开发清单

固定包含 Task 总览、依赖关系、推荐实施顺序、逐 Task 明细和验证矩阵，存在待确认项时增加对应章节。每个 Task 明细至少包含目标、实现描述、设计定位、核心代码或计划路径、依赖、验收口径、阶段化状态和必要证据。每个 Task 只承载少量可独立推进、验收的操作；复杂业务使用父子 Task，父 Task 汇总能力，子 Task 承担可交付结果，且父、子 Task 都必须有明细和设计定位。按业务结果拆分，不按技术层拆分。

### 系统分析

只回答：目标和非目标、真实现状、差异、关键结论、影响范围、风险与待确认项。不要提前展开接口字段、SQL、异常分支等详细实现，除非它们本身就是待决策风险。

### 详细设计

只描述需要设计的复杂部分，尽量达到可直接实现的粒度：明确模块职责、输入输出、字段/状态变化、异常与边界，并给出关键代码片段或覆盖全部关键分支的完整伪代码。较长的读写、调用、状态流转或异步流程必须附 Mermaid。简单模块可以省略；不要重复系统分析中的背景和状态表。

### 当前上下文

保持在约 50 行内，只记录活跃 Task、有效结论、当前阻断、必须复验项和下一步。不要记录“最近状态变化”或日期流水。

### 测试计划与过程记录

测试计划是矩阵和证据索引，不复制测试报告正文。过程记录默认不读，除非用户要求审计、复盘或需要历史根因。

## 模板

需要创建文件时使用 `references/templates/` 中对应模板。删除不适用章节，不保留无意义占位符，也不为填满模板编造内容。

默认路径：

```text
doc/<工单号>/
  开发清单.md              # 跟踪任务时优先创建
  系统分析.md              # 按需
  详细设计.md              # 按需
  当前上下文.md            # 按需
  测试计划.md              # 按需
  过程记录.md              # 按需
```

项目已有稳定命名和目录时沿用现状，不为套模板重命名。
