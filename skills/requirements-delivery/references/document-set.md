# 文档集

当需要新建、迁移或修复 requirements-delivery 工作文档时，读取本文件。

## 阶段化默认文件

| 文件 | 用途 | 默认内容 |
|------|------|----------|
| `当前上下文.md` | 权威恢复入口与短上下文基线 | 权威文件索引、当前阶段、当前有效结论、已失效结论、活跃 Task、下一步、必须复验项 |
| `系统分析.md` | 系统分析阶段的权威分析基线 | 背景目标、现状分析、差异分析、头脑风暴验证结论、方案方向、影响范围、风险与假设 |
| `详细设计.md` / `<阶段>-详细设计.md` | 头脑风暴收敛后的实现级设计 | 模块设计、数据与权限、接口流程、查询/SQL/性能、兼容异常、Task 映射 |
| `开发清单.md` | 权威任务与状态基线 | 最小粒度 Task、验收口径、详细设计索引、阶段化状态、最新状态、验证证据和过程记录索引 |
| `测试计划.md` | 按需验证基线 | 验证范围、测试场景、测试数据、预期结果、执行记录、遗留风险 |
| `过程记录.md` | 按需人工审计与历史流水 | 变更记录、Bug 修复记录、审计明细、复盘记录、历史实现迁移记录 |

不要一次性创建所有文件。默认阶段顺序：

1. 系统分析阶段先创建或更新 `系统分析.md`，记录多轮头脑风暴后的有效结论、待确认项和方案方向。
2. 头脑风暴和用户确认收敛后，创建 `详细设计.md`；需求分期或专题明显时，使用 `<阶段>-<主题>详细设计.md`，并让 `详细设计.md` 作为索引。
3. 详细设计足以指导编码后，再创建或更新 `开发清单.md`，从详细设计反推 Task。
4. `测试计划.md`、`过程记录.md` 只在验证矩阵、审计、复盘、Bug 过程或跨会话恢复确有需要时创建。

只有在用户明确要求单文件，或任务小到不值得拆分且不需要跨会话执行时，才使用单文件结构。

首次创建工作文档时，优先使用 `references/templates/` 下的模板：

| 文件 | 模板 |
|------|------|
| `当前上下文.md` | `references/templates/当前上下文.template.md` |
| `系统分析.md` | `references/templates/系统分析.template.md` |
| `详细设计.md` | `references/templates/详细设计.template.md` |
| `开发清单.md` | `references/templates/开发清单.template.md` |
| `测试计划.md` | `references/templates/测试计划.template.md` |
| `过程记录.md` | `references/templates/过程记录.template.md` |

模板基于 EXEPD-217807 的文档结构抽象而来。创建时只填当前需求确有依据的内容；没有事实依据的段落保留占位或标记“待确认”，不要编造。

## 职责边界

- `当前上下文.md` 负责可恢复状态、当前有效结论、已失效结论、活跃 Task、下一步和读取顺序。
- `系统分析.md` 负责需求理解、现状差距、头脑风暴验证结论和方案方向。
- `详细设计.md` / `<阶段>-详细设计.md` 负责足以指导编码的实现设计。
- `开发清单.md` 负责任务拆分、执行状态、验收口径、详细设计索引、最新状态、证据链接和过程记录索引。
- `测试计划.md` 负责验证范围、用例、预期结果、执行记录和遗留风险。
- `过程记录.md` 负责长篇历史和人工审计材料。

某个文件的结论影响其他文件时，必须先同步下游文件，再继续实现。

## 当前上下文.md

此文件应足够短，方便每次继续任务时先读，通常控制在 100-150 行。

推荐结构：

- 权威文件索引
- 当前阶段
- 活跃 Task
- 当前有效结论
- 已失效结论
- 最近状态变化，最多保留 3-5 条高价值记录
- 下一步
- 必须复验项
- 默认读取顺序

推荐表格：

| 主题 | 当前有效结论 | 依据 | 影响 Task |
|------|------|------|------|

| 旧结论 | 失效原因 | 替代结论 | 禁止回退点 |
|------|------|------|------|

## 系统分析.md

优先使用这些章节：

- 背景与目标
- 当前阅读规则
- 当前有效设计摘要
- 现状实现
- 差异分析
- 头脑风暴验证结论
- 方案方向
- 影响范围
- 风险与假设

系统分析只保留当前分析基线、已验证方向和必要约束。它不是最终详细设计，也不是开发清单。长篇变更历史、Bug 历史、多轮审查流水和追责记录迁入 `过程记录.md`。

旧设计仍需保留时，使用 `[已失效]` 标记，并指向替代结论。

## 详细设计.md

详细设计在系统分析和多轮头脑风暴收敛后创建。它必须能回答“开发清单中的每个 Task 为什么这样做、改哪里、怎么验收”。

推荐结构：

- 设计基线
- 总体设计
- 模块设计
- 数据与权限设计
- 接口与流程设计
- 查询 / SQL / 性能设计
- 兼容、异常和回滚设计
- Task 映射
- 待确认项

需求分期或专题明显时：

```text
doc/<工单号>/
  详细设计.md                  # 索引、共用边界和失效口径
  一期-<主题>详细设计.md
  二期-<主题>详细设计.md
```

`开发清单.md` 的每个 Task 必须引用具体详细设计章节，例如 `一期-<主题>详细设计.md#6-明细生成服务`。

## 过程记录.md

此文件默认追加写入，除非要纠正事实错误。适合记录：

- 变更记录
- Bug 修复记录
- 审计明细
- 多轮审查记录
- 复盘记录
- 历史实现迁移记录

活跃文档应链接到过程记录，而不是复制长表格。

## 路径与命名

优先使用稳定命名：

```text
doc/<工单号>/
  当前上下文.md
  系统分析.md
  详细设计.md
  开发清单.md
  测试计划.md
  过程记录.md
```

如果现有项目已经使用长文件名，不要随意重命名。新增 `当前上下文.md` 和 `过程记录.md`，并在 `当前上下文.md` 中索引已有文件名。
