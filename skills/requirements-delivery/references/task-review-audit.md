# Task 状态与审计

只在创建或维护 `开发清单.md` 时读取。

## Task 规则

- Task 按可独立验收的业务结果拆分，不按技术层拆分。
- 每个 Task 只保留一份状态：`待处理`、`实现中`、`待验证`、`已完成`、`阻断`。
- 每个 Task 至少包含：范围、不处理、设计定位、验证命令或场景、证据、下一步。
- 父 Task 只做汇总；子 Task 未完成时父 Task 不得标记完成。
- 设计定位缺失时，先补设计或明确“不涉及”，再实现。

## 审计

完成前检查：范围、验收信号、代码变更、验证结果、未覆盖范围。只保留结论和证据，不复制终端流水。

用户要求提交时，按文件或 hunk 审计当前 Task 的提交边界；不自动提交，也不把其他 Task 的改动归入当前 Task。
