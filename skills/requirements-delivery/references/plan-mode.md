# 系统分析 Plan 模式

系统分析阶段是**只读 + 阻塞问答**的交互式决策流程，不是另一个长文档，也不要求用户自行审阅方案清单。若问题是视觉布局或页面方案，可调用视觉伴侣；若问题是图表、模拟或数据展示，使用 `visualize`。

模型无法自行把宿主切进 Plan 模式。按实际情况二选一：

- 宿主已在 Plan 模式：用 `exit_plan_mode` 交付分析与待确认项，等待批准。
- 宿主不在 Plan 模式：本文件的只读约束 + `ask_user_question` 就是等价阻塞点，效果相同。

## 运行规则

1. 先读取需求、仓库规则、相关代码、模型和可用运行态证据。
2. 能从证据确定的内容直接写入系统分析。
3. 本阶段只允许读和写流程文档，不得修改生产代码。
4. 发现会改变实现、接口、数据、权限、兼容或验收的未知项时，立即调用 `ask_user_question` 阻塞提问。
5. 一次只问一个最关键的问题；工具返回后，再继续依赖该答案的分析、设计或实现。
6. 用户回答后，立即把答案写回系统分析，更新结论、范围和验收信号。
7. 所有关键决策闭合后，才进入详细设计或实现。

## 提问格式

```text
已确认事实：<证据>
待确认问题：<具体问题>
推荐：<方案>，因为<原因>
取舍：<选择与代价>
请确认：<一句可以直接回答的问题>
```

## 硬边界

- 不把待确认事项只列在文档中等待用户阅读。
- 不把推荐方案当成用户确认。
- 不用正文提问代替 `ask_user_question`：正文提问不阻塞，会被当成"问完继续做"。
- 用户未回答前，只能做不依赖该决策的只读调查。
- 没有关键未知项时，直接记录“已核查，无需额外决策”。
- 分析结束的标志是"全部决策闭合 + 出口校验通过"，不是"分析段落写完"。写完后直接改代码属于流程违规。
