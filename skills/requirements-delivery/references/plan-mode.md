# 系统分析 Plan 模式

进入系统分析阶段即自动使用本模式。它是交互式决策流程，不是另一个长文档，也不要求用户自行审阅方案清单。若问题是视觉布局或页面方案，Plan 可调用视觉伴侣；若问题是图表、模拟或数据展示，使用 `visualize`。

## 运行规则

1. 先读取需求、仓库规则、相关代码、模型和可用运行态证据。
2. 能从证据确定的内容直接写入系统分析。
3. 发现会改变实现、接口、数据、权限、兼容或验收的未知项时，立即在聊天中提问。
4. 一次只问一个最关键的问题；等待用户回答后，再继续依赖该答案的分析、设计或实现。
5. 用户回答后，立即把答案写回系统分析，更新结论、范围和验收信号。
6. 所有关键决策闭合后，才退出 Plan 模式并进入详细设计或实现。

## 提问格式

```text
已确认事实：<证据>
待确认问题：<具体问题>
推荐：<方案>，因为<原因>
取舍：<选择与代价>
请确认：<一句可以直接回答的问题>
```

## 硬边界

- 不把待确认事项只列在文档中等待用户阅读。
- 不把推荐方案当成用户确认。
- 用户未回答前，只能做不依赖该决策的只读调查。
- 没有关键未知项时，直接记录“已核查，无需额外决策”。
