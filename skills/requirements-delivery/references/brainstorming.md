# Brainstorming 分支

这是 requirements-delivery 的需求澄清能力，不是独立 Skill。进入系统分析时，如果存在会改变实现、接口、数据、权限、兼容或验收的未知项，使用 Codex Plan 模式完成问答。

## 规则

1. 先读取需求、代码、模型和仓库规则。
2. 能由证据确定的内容直接写入系统分析。
3. 只保留真正影响实现的未知项，一次向用户问一个最关键的问题。
4. 提供事实、推荐和取舍，等待用户回答；未回答前不继续依赖该决定的设计或实现。
5. 用户回答后立即回写系统分析，再处理下一个未知项。

不要生成独立方案清单、spec 或要求用户自行修改文档。没有关键未知项时，记录“已核查，无需额外决策”。
