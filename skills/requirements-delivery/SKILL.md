# Requirements Delivery

把需求文档转成可恢复、可验证、可跨会话持续推进的交付工作流。默认使用阶段化多文件工作集，避免一次性创建所有材料，也避免把历史流水塞进当前上下文。

如果用户只提供工单号，默认到 `doc/<工单号>/` 查找文档；如果用户指定路径，以用户路径为准。新建或更新配套文档时，放在同一目录。

## 阶段化文档契约

| 文件 | 用途 | 默认读取 |
|------|------|----------|
| `当前上下文.md` | 新会话恢复入口：有效结论、活跃 Task、下一步、复验项 | 必读 |
| `系统分析.md` | 系统分析阶段的权威分析基线、头脑风暴结论和设计方向 | 分析阶段必读；实现阶段按索引读取 |
| `详细设计.md` / `<阶段>-详细设计.md` | 多轮头脑风暴后形成的实现级设计；可拆分为分期/专题详细设计 | 执行 Task 前按开发清单索引精读 |
| `开发清单.md` | Task、阶段状态、验收口径、验证证据、过程记录索引和详细设计索引 | 设计完成后创建；实现阶段必读总览和活跃 Task |
| `测试计划.md` | 验证矩阵和执行记录 | 按需创建；按活跃 Task 精读 |
| `过程记录.md` | 历史、审计、复盘、长篇 Bug 过程 | 按需创建；默认不读 |

文档不要求一次性全部创建。默认顺序是：先产出 `系统分析.md`；多轮头脑风暴和设计验证收敛后，再产出 `详细设计.md` 或分期详细设计；之后根据详细设计产出 `开发清单.md`；`测试计划.md`、`过程记录.md` 等材料按任务风险和恢复需要创建。

`开发清单.md` 中每个 Task 必须包含“设计定位”，指向 `详细设计.md#...` 或具体分期详细设计章节。执行 Task 时，必须先读取该设计定位对应章节，再改代码或更新状态。

## 按需加载

只打开当前决策需要的 reference：

| 当前问题 | 读取 |
|------|------|
| 新建/迁移文档结构、文件职责、命名 | `references/document-set.md` |
| `/analyze`、`/sync`、新会话恢复、实现和验证顺序 | `references/workflow.md` |

不要一次性读取所有 references。

## 启动门禁

1. 先读仓库规则，包括 `AGENTS.md`。
2. 继续已有需求时，先读 `当前上下文.md`，再读 `开发清单.md` 总览和活跃 Task。
3. 按活跃 Task 精读 `开发清单.md` 中“设计定位”指向的详细设计章节；没有详细设计索引时，先补齐设计索引，不直接实现。
4. 按活跃 Task 精读相关 `系统分析.md` 和 `测试计划.md` 章节。
5. 改代码前，保证系统分析、详细设计、当前上下文、Task 状态和验证口径一致。
6. 结论变化时，先同步受影响活跃文档，再继续实现。

## Fast 模式

只有用户明确说 `fast模式`、`--fast`、`快速模式` 或“最快完成代码”时启用。

- 目标：以最快速度完成代码。
- 不调用任何内置方法子技能。
- 不走 TDD 流程，不要求先写失败测试。
- 不记录过程文档，不更新 `当前上下文.md`、`系统分析.md`、`详细设计.md`、`测试计划.md`、`过程记录.md`。
- 只更新 `开发清单.md` 中相关 Task 的阶段状态、当前状态和必要证据。
- 仍遵守仓库规则、用户明确要求和代码安全底线；无法验证时在最终回复说明。

## 硬规则

- 区分文档假设、代码真实状态、已验证的模型/配置真实状态。
- Task 宁可拆细，不混合多个不相关目标。
- 系统分析阶段必须进行头脑风暴，并通过多轮验证收敛需求、边界、方案和风险；不能把首次理解直接写成最终设计。
- `系统分析.md` 只承载分析基线和已验证方向；详细实现设计应在头脑风暴收敛后进入 `详细设计.md` 或分期详细设计文档。
- `开发清单.md` 必须由详细设计反推生成，Task 必须索引到对应详细设计章节；执行 Task 时必须读取该索引。
- 前端页面类改动的最小验证优先使用 Playwright 访问项目运行中的页面，并按路由定位到对应修改页面；需要 UI 还原时必须对照 UI 原型或截图检查。除非用户明确要求、项目文档强制要求或修改触及构建配置/依赖/跨端产物，不要把前端构建作为默认验证步骤。
- 涉及数据和 SQL 时写清查询策略；复杂查询优先数据库下推。
- SQL 涉及 `UNION ALL`、`CASE`、`COALESCE`、`NULL`、占位列或跨类型比较时，必须审查渲染 SQL 和 PostgreSQL 类型兼容性。
- 公开分页接口优先复用平台分页结构，如 `ListPageResult<T>`。
- `开发清单.md` 不写审查明细；长篇审查、复盘、责任归因写入 `过程记录.md`，开发清单只留状态、详细设计索引和过程索引。
- `当前上下文.md` 只写当前有效结论、已失效结论、复验项和下一步；禁止新增“最近状态变化”、日期流水、变更记录、审查过程、复盘过程或责任归因。结论变化应改写/合并到现有表格行，历史过程写入 `过程记录.md`。
- 不要自动提交。只有用户明确要求时，才暂存或提交。
- 用户要求提交时，提交前必须重新读取仓库 VCS/文档规则，查看近期提交标题格式，并确认 staged/unstaged/untracked 边界；代码变更和文档变更必须按仓库规则拆分提交，不能用默认 Conventional Commit 替代工单分支既有格式。

## Skill 协同

按任务需要再加载：

- `$epaas-router`：宽泛 ePaaS 后端问题分流。
- `$epaas-server`：Hook、事件、MQ、定时任务或服务链路。
- `$datarecord`：查询、计数、EQL、关联路径和数据更新规则。
- `$sql-template`：SQL 编写、渲染、模板、动态 SQL 或 PostgreSQL 兼容性审查。

内置方法子技能按阶段读取：

- `subskills/superpowers/brainstorming/SKILL.md`：系统分析阶段必须读取并使用；fast 模式除外。
- `subskills/superpowers/systematic-debugging/SKILL.md`：Bug、验证失败、运行异常或根因不清。
- `subskills/superpowers/verification-before-completion/SKILL.md`：声称完成、修复、通过或准备交付前。
